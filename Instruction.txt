NeuroSight Setup Instructions (Updated)

Overview
NeuroSight detects and classifies brain tumors from MRI scans using an ensemble
deep learning model (WaveFusionNet + SVM + XGBoost), and adds a full care
workflow: clinician dashboard, patient mobile PWA, explainable-AI heatmaps,
medical chatbot, blockchain medical records, and real-time emergency alerts.

Components and ports:
- Backend API (FastAPI)        : http://127.0.0.1:8000   (docs: /docs)
- Frontend dashboard (Vite)    : http://localhost:5173
- Mobile PWA (Vite)            : http://localhost:5174
- Chatbot microservice         : http://127.0.0.1:8001   (optional)

Prerequisites
- Python 3.11
- Node.js (18+ recommended)
- npm
- PostgreSQL + pgAdmin
- Git
- (optional) Hardhat / local Ethereum node for the blockchain feature

1) Create Database
1. Open pgAdmin.
2. Create a database named brain_tumor.
   (Tables are created automatically on first backend startup.)

2) Open Project
1. Clone the repository:
   git clone https://github.com/TharunKalugalla/Brain-tumor-detection-and-classification-by-ensemble-approach-based-deep-learning-system.git
2. Open the project root in VS Code.

3) Backend Setup
1. Go to backend folder:
	cd backend
2. Create venv:
	py -3.11 -m venv .venv
3. Activate venv:
	.\.venv\Scripts\Activate
4. Upgrade pip tools:
	python -m pip install --upgrade pip setuptools wheel
5. Install backend requirements:
	pip install --no-cache-dir -r requirements.txt
6. Create environment file:
	copy .env.example .env
7. Edit .env and set real values:
	- DATABASE_URL: change the password to your own PostgreSQL password,
	  e.g. postgresql+psycopg2://postgres:<yourpassword>@localhost:5432/brain_tumor
	- SECRET_KEY: REQUIRED. Must be a strong random value of at least 32 chars.
	  The app REFUSES to start with the example/insecure default. Generate one:
		python -c "import secrets; print(secrets.token_hex(32))"
	  Each developer can use their own key for local dev. Tokens signed with one
	  key are invalid under another, so re-login after changing it.
	- Add SMTP settings from section 13 if you want email enrollment to work.
	- Add blockchain settings from section 12 if you want the ledger feature.
8. Return to project root:
	cd ..

Note on model files:
	The ensemble artifacts live in backend/tumor_models/
	(wavefusionnet_final.keras, svm_clf.pkl, xgb_clf.pkl, scaler.pkl,
	 ensemble_weights.json) and are required for inference.

IMPORTANT — One-time warning for existing team members:
	backend/.env has been removed from git tracking (it should never have been committed).
	When you pull, git will DELETE your local backend/.env if it was tracked before.
	Before pulling: copy your backend/.env to a safe place (e.g. Desktop).
	After pulling: put it back. Future pulls will never touch it again.

4) Run Backend (Current Method)
1. From project root, run:
	npm run dev
2. API docs:
	http://127.0.0.1:8000/docs
3. Health endpoints:
	http://127.0.0.1:8000/health
	http://127.0.0.1:8000/health/model

Note:
- npm run dev at root uses backend/.venv Python directly.
- First start runs a model + XAI warmup (loads weights, compiles TensorFlow
  graphs). This is a one-time cost of ~5-15 min; /health returns 200 when ready.
  Set SKIP_WARMUP=true in .env to skip it for dev (first request is then slow).
- Uploaded MRI and document folders are served (JWT-gated) from:
  /uploaded_mris and /uploaded_docs

6) Frontend Setup and Run
1. Go to frontend folder:
	cd frontend
2. Install dependencies:
	npm install
3. Start frontend:
	npm run dev
4. Open URL shown by Vite (usually http://localhost:5173).

Optional: Run frontend from root
- npm run dev:frontend

7) Test Database Connection
1. Activate backend venv and run from backend folder:
	python test_db.py

If you use a separate test database URL:
- set TEST_DATABASE_URL=postgresql+psycopg2://<user>:<password>@<host>:5432/<dbname>
- python test_db.py

8) Managed Launcher (preferred — runs the whole system)
From the project root:
	npm start            -> backend + dashboard (+ chatbot if model present)
	npm run start:mobile -> same, plus the mobile PWA on :5174
	npm stop             -> stop all services cleanly

The launcher frees stale ports, starts each service detached, records PIDs to
.neurosight-pids.json, then waits for backend /health (model warmup 5-15 min).

Skip the warmup wait:
	powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-system.ps1 -Mobile -NoWait

 # Mobile Chatbot Instructions
9) Mobile Chatbot Initial Setup (run once before using the chatbot)
Note: The backend venv must be activated before running any of these steps.
      All commands run from the project root unless stated otherwise.
      If the chatbot service (:8001) is not running, the backend automatically
      falls back to a TF-IDF classifier — no crash, but reduced answer quality.

Step 1 - Install chatbot dependencies (inside activated backend venv):
	pip install -r backend/chatbot/requirements.txt

Step 2 - Download model.safetensors from Google Drive (NOT in git — too large):
	Download link:
		https://drive.google.com/file/d/1BGm0flcAK47gmsEV8-fEeVsZfPq9qUOk/view?usp=drive_link
	Place the downloaded file at:
		backend/chatbot/model/neurosight_distilbert/model.safetensors
	The following files ARE already in the repository (no download needed):
		backend/chatbot/model/faiss_index.bin
		backend/chatbot/model/qa_dataset_final.csv

	IMPORTANT: Without model.safetensors the chatbot microservice will not start.
	           The main backend (port 8000) will still work using the TF-IDF fallback.

Step 3 - Run the chatbot microservice in a separate terminal (port 8001):
	uvicorn backend.chatbot.microservice:app --port 8001

Step 4 - Run the main backend as usual in another terminal (port 8000):
	npm run dev
	   OR
	uvicorn backend.main:app --reload --port 8000

Both terminals must stay open for the chatbot to work.
(Or use npm start, which launches the chatbot automatically when the model is present.)
If port 8001 is not running, the chatbot automatically falls back to
the TF-IDF classifier (Step 2) — no crash, but reduced answer quality.

10) Mobile App Setup and Run
First-time setup (install dependencies once):
	cd mobile
	npm install
	cd ..

Run (managed launcher — preferred):
	From the project root:
		npm run start:mobile
	This starts the whole system plus the mobile PWA:
		backend (:8000), frontend dashboard (:5173),
		chatbot (:8001, only if model.safetensors present),
		and mobile (:5174).
	It frees stale ports first, launches each service detached, records
	PIDs to .neurosight-pids.json, then waits for backend /health (model
	warmup can take 5-15 min). Mobile UI is reachable at http://localhost:5174
	as soon as Vite starts; backend-dependent features wait for warmup.

	Stop everything cleanly:
		npm stop

	Options (call the script directly to skip the warmup wait):
		powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-system.ps1 -Mobile -NoWait

Manual run (fallback — single service only, no port/PID cleanup):
	cd mobile
	npm run dev
	Open the URL shown by Vite (usually http://localhost:5174).


11) Emergency feature (SOS alerts)
- Purpose: mobile SOS sends structured alerts to `/mobile/notify`. The backend persists an emergency `ChatMessage` and emits a realtime `emergency_alert` event to clinician dashboards via Socket.IO.
- Install Socket.IO client (frontend):
		cd frontend
		npm install --save socket.io-client
- Dev run order to test locally:
		1. Start backend: `npm run dev` (or `uvicorn backend.main:app --reload --port 8000`)
		2. Start frontend dashboard: `cd frontend && npm run dev`
		3. Start mobile app: `cd mobile && npm run dev`
		4. Trigger SOS from mobile; verify alerts appear on dashboard and realtime popup
- Notes:
	- `socket.io-client` is required by the dashboard to receive live emergency alerts (push). Without it the dashboard will only show alerts via polling endpoints.
	- Geolocation (`navigator.geolocation`) requires HTTPS on devices; `localhost` works for most dev setups.

12) Blockchain Medical Records (optional)
Required only for the "Save to Blockchain" medical-history feature.

Step 1 - Deploy the contract:
	cd blockchain
	npm install
	npm run compile
	npm run deploy:local   (local node)   OR   npm run deploy   (ganache network)
	cd ..

Step 2 - Add these to backend/.env:
	PINATA_API_KEY=your_pinata_api_key
	PINATA_SECRET_KEY=your_pinata_secret_key
	ETH_PRIVATE_KEY=0xyour_node_private_key
	FERNET_KEY=your_fernet_key_base64

	Generate a Fernet key:
		python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

--- Step B: Testing on a real phone ---
Each person uses their own local backend and database.
ngrok creates a public URL so your phone can reach your laptop's backend.

Your steps:
	1. Start your backend: npm run dev  (from project root)
	2. Open a second terminal and run ngrok:
	   .\ngrok.exe http 8000
	   (ngrok.exe is already in the project root)
	3. First time only — add your ngrok authtoken (sign up free at dashboard.ngrok.com):
	   .\ngrok.exe config add-authtoken YOUR_TOKEN
	4. Copy the URL ngrok shows (e.g. https://abc123.ngrok-free.app)
	5. Send the URL to Fathima Shameeha — she will update VITE_API_URL in Vercel and redeploy
	   (only she has access to the Vercel project)
	6. Once redeployed, open https://neurosight-app.vercel.app on your phone — login will work

Note: ngrok URL changes every time it restarts. Repeat steps 2–6 each session.
